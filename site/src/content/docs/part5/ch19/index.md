## 开场

把镜头换到客户一侧。临江精工决定引入厂商 FDE 之前，采购负责人把合同草案摊在厂长面前，说了一句实在话：人进场之后，天天接触的是咱们的产线数据、工艺参数和真实流程。等他们撤场，咱们能不能自己把系统跑下去，全看现在这份合同怎么签。

前面三章站在厂商一侧算账。这一章站在买方一侧，给一份能直接拿去用的清单：用厂商 FDE 时，合同里必须盯住的四件事。

## 白话讲解

第一件，IP 归属。FDE 在你的现场写出的代码、配出的流程、整理出的数据资产，归谁？合理的分法是：厂商的产品本体和通用组件归厂商；用你的数据、你的业务规则做出来的东西，你至少要有完整的使用权，最好归你。这一条不写清，撤场那天就可能发现，自己花钱请人做的系统，核心部分带不走。

第二件，数据不用于训练模型。你的产线数据、客户名单、工艺参数，是你的家底，必须在合同里写明：厂商不得把这些数据用于训练它自己的模型，也不得用于服务其他客户，尤其是你的同行。微软在推出 Frontier Company 时专门把「客户数据与 IP 不用于训练模型」写进公开承诺，说明这件事已经是大客户谈判的标配，你提这个要求，一点都不过分。

第三件，退出策略。Gartner 给企业的建议很直接：请 FDE 进场之前，先把退出策略定好。包括驻场结束的条件是什么、系统文档和代码交到什么程度才算交接完成、厂商撤场后留多长的答疑期、如果中途要换供应商，数据和配置怎么导出。想在合作愉快时谈分手条款，正因为那时双方都还讲道理。

第四件，知识转移。要求厂商的人在现场带你的人：关键岗位双人跟学、核心操作留录像和手册、每周有固定答疑。判断标准很粗暴：如果你的工程师在撤场后第一个月，遇到常见故障只能打电话找厂商，这次驻场的知识转移就是失败的。

![合同里的四面盾](/baihua-fde/images/ch19-contract-shield.svg)

图：买方签约时要立起的四面盾，少一面，撤场之后就多一个窟窿。

还有一个谈判顺序的小建议：不要等商务条款全都谈完，才把这四件事拿出来。那时双方都想赶紧签完，细节最容易被人情和进度压过去。正确顺序是反的：在报价之前，先和对方的技术与法务把 IP、数据、退出、知识转移四件事谈成原则，写成一页纸的共识，再去谈价格和工期。原则先行的另一个好处是能提前试出对方的成色。愿意坐下来认真谈退出和数据条款的厂商，通常对自己的交付有底气；在这些条款上反复打太极的厂商，进场之后大概率也会在别的地方打太极。

下面这张表可以当合同谈判的检查清单直接用，逐项打勾再签字。

| 条款 | 要写清什么 | 不写清的下场 |
| --- | --- | --- |
| IP 归属 | 现场定制代码、流程配置、数据资产的归属与使用权 | 付了钱，核心成果带不走 |
| 数据用途 | 数据不得用于训练厂商模型，不得用于其他客户 | 家底变成厂商服务同行的本钱 |
| 保密与同行隔离 | 同一团队不得同时服务直接竞争对手，或做隔离安排 | 你的打法经厂商之手流向同行 |
| 退出策略 | 结束条件、交接标准、撤场后答疑期、数据导出格式 | 撤场即断档，换供应商重来一遍 |
| 知识转移 | 双人跟学、手册与录像、内部人员考核通过才算交接 | 系统在跑，没人会修 |
| 目标与验收 | 结果指标口径、验收人、口径变更的处理办法 | 做完不认账，两边扯皮 |
| 人员条款 | 关键人员名单、换人需买方同意 | 签约时是专家，进场变新手 |

## 陆远的现场

临江精工的合同谈判，陆远作为厂商侧的人坐在桌子对面，感受很真实。采购负责人提的四条要求，厂长全程在场背书：现场代码和报警码对照表这类数据资产归临江；临江的数据不用于训练任何模型；撤场验收以王工能独立处理常见故障为准；关键人员变更提前打招呼。

老潘私下跟陆远说，这份合同签得越细，对厂商其实越是好事。要求清楚的客户，目标也清楚，最后验收不扯皮。真正难做的，是那些什么都不提、进场后什么都想要的客户。这个视角后来写进了公司的合同模板：新客户谈判时，厂商主动把数据和退出条款摆上桌，先把丑话说在前面。

王工后来的自建队（第六篇会讲），种子正是这份合同里知识转移条款带出来的人。买方在签约时多问一句「我的人怎么学会」，两年后就多一支自己的队伍。

## 翻车现场

一家企业请厂商 FDE 做智能客服系统，合同签得痛快，IP 和数据条款都是厂商模板里的默认文字，没细看。系统上线效果不错，合作两年。第三年想换一家性价比更高的供应商时，对方打开系统一看：核心的问答流程配置在厂商平台的专有格式里，导不出来；两年来积累的问答数据，按合同属于合作成果，厂商只同意给汇总报表。这家企业只能两个选择：继续按原价续约，或者推倒重来，把两年的积累清零。

它不是被技术锁住的，是被合同锁住的。而解开的时机，只在签约那几天存在过。

## 要点回顾

- 买厂商 FDE，签约前先定四件事：IP 归属、数据用途、退出策略、知识转移。
- 数据不用于训练模型，已经是大厂公开承诺的标配，买方提出来理直气壮。
- 退出策略要在关系最好的时候谈，那时双方都还讲道理。
- 知识转移的验收标准：你的人能独立处理常见故障，才算交接完成。
- 被锁住的企业多半不是被技术锁住的，是被当初没细看的合同锁住的。

## Kata

1. 拿一份你经手过的外包或采购合同，对着本章的检查清单逐项对照，缺了哪几项？缺失的每一项，补一句你认为合理的条款文字。
2. 如果厂商对「数据不用于训练模型」一条含糊其词，你会要求对方给出哪三种可验证的安排，而不只是一句口头承诺？
3. 设想你要在六个月后让厂商 FDE 撤场，从今天起倒推，你的团队每个月分别要接住什么？
